# 디자인 시스템 방향 (PHASE 0)

> 이 문서는 PHASE 2에서 `src/app.css`의 `@theme` 토큰으로 그대로 구현된다.
> **토큰의 단일 진실 공급원은 CSS다.** 이 문서는 "왜 이 값인가"를 남긴다.

---

## 1. 디자인 한 줄 목표

> 아이가 첫 화면을 보고 **"우와, 게임이다"** 라고 말해야 한다.
> 동시에 부모가 보고 **"잘 만든 서비스네"** 라고 느껴야 한다.

이 둘을 동시에 만족하는 지점이 이 프로젝트의 디자인 좌표다.
귀엽되 유치하지 않고, 화려하되 산만하지 않다.

### 하지 않는 것 (Anti-goals)

| 안 됨                                 | 이유                                       |
| ------------------------------------- | ------------------------------------------ |
| 원색 팔레트(순수 빨강·파랑·노랑) 남발 | 유치원 교재처럼 보인다                     |
| 모든 요소에 glow / bounce             | 시선이 갈 곳을 잃는다. 화면당 주인공은 1개 |
| 순수 검정(`#000`) 텍스트              | 판타지 톤이 깨진다. 보라빛 먹색을 쓴다     |
| 흰 배경 + 회색 카드의 "관리자 화면"   | 공부 사이트처럼 보인다                     |
| 무섭거나 사실적인 몬스터              | 저학년이 이탈한다                          |
| 텍스트 위주의 피드백("정답입니다")    | 게임이 아니라 시험지가 된다                |

## 2. 색상 토큰

순수 채도를 낮추고 **보라-하늘 축**을 중심축으로 잡는다. 금색·핑크는 **보상에만** 쓴다.
"금색이 보이면 좋은 일이 일어난 것"이라는 규칙을 아이가 학습하게 만든다.

### magic (Primary — 마법 보라)

| 토큰  | 값        | 용도                  |
| ----- | --------- | --------------------- |
| `50`  | `#F3F0FF` | 패널 배경             |
| `100` | `#E7E0FF` | 비활성 카드           |
| `200` | `#CFC2FF` | 테두리                |
| `300` | `#B29CFF` | 보조 아이콘           |
| `400` | `#9575FF` | 그라디언트 밝은 쪽    |
| `500` | `#7C5CFF` | **주 버튼 / 브랜드**  |
| `600` | `#6742E8` | 버튼 hover            |
| `700` | `#5231BC` | 버튼 press            |
| `800` | `#3E2590` | 딥 배경               |
| `900` | `#2B1A66` | 배틀/레벨업 암전 배경 |

### sky (Secondary — 하늘·물)

`50 #EEF9FF` · `100 #D9F2FF` · `200 #B5E6FF` · `300 #83D6FF` · `400 #4FC3F7` · `500 #22ABEE` · `600 #0E8CCB` · `700 #0B6F9F`

### mint (Success — 정답·성장)

`300 #99F6E4` · `400 #5EEAD4` · `500 #2DD4BF` · `600 #14B8A6`

### gold (Accent — 보상·별·EXP)

`300 #FFE08A` · `400 #FFD25E` · `500 #FFC93C` · `600 #F5A623`

### candy (Accent — 강조·하트)

`300 #FFC2DA` · `400 #FF9EC4` · `500 #FF7AAE` · `600 #F25892`

### ember (Danger — 오답·적)

`300 #FFB8B8` · `400 #FF8B8B` · `500 #FF6B6B` · `600 #E85252`

> **부드러운 레드**를 쓰는 이유: 오답은 실패가 아니라 "다시 해보자"여야 한다.
> 강한 빨강은 아이에게 처벌로 읽힌다.

### ink (텍스트 — 보라빛 먹색)

`900 #2A2050` (본문) · `700 #4A3F7A` (보조) · `500 #6F659B` (설명) · `400 #9A93BC` (placeholder)

### 배경 그라디언트

```css
--gradient-sky: linear-gradient(180deg, #c9e9ff 0%, #e4e0ff 55%, #f6eeff 100%);
--gradient-magic: linear-gradient(135deg, #9575ff 0%, #7c5cff 50%, #6742e8 100%);
--gradient-gold: linear-gradient(135deg, #ffe08a 0%, #ffc93c 100%);
--gradient-night: radial-gradient(120% 90% at 50% 10%, #3e2590 0%, #2b1a66 60%, #1b1042 100%);
```

`night`는 **레벨업·보스 대결에서만** 쓴다. 평소 밝은 화면과 대비되어 "특별한 순간"이 된다.

### 대비 검증 규칙

`ink-900` on `magic-50` / 흰 텍스트 on `magic-500` / `ink-900` on `gold-500` 조합은
전부 4.5:1 이상을 만족하도록 PHASE 2에서 스크립트로 검증한다(`npm run check:contrast`).

## 3. 타이포그래피

| 역할      | 폰트                 | 라이선스 | 용도                             |
| --------- | -------------------- | -------- | -------------------------------- |
| `display` | **Jua**              | OFL      | 로고, 제목, 버튼, 숫자(EXP/레벨) |
| `body`    | **Noto Sans KR**     | OFL      | 본문, 설명, 폼                   |
| `hanja`   | **Noto Sans KR 700** | OFL      | 한자 본체 글리프                 |

**한자를 고딕(Sans) 700 으로 쓰는 이유** — ⚠️ PHASE 0 의 결정을 뒤집었다.

처음에는 명조(Noto Serif KR)를 골랐다. "획의 시작·끝·삐침이 명확해야 학습이 된다"는 이유였다.
PHASE 18 에서 실제 렌더링을 나란히 놓고 비교했더니 **틀린 판단이었다.**

명조는 획이 적은 한자에서 가로획이 머리카락처럼 얇아지고 오른쪽 끝에만 삼각형 세리프가 남는다.
그 결과 `二` 가 아이 눈에 **한자가 아니라 화살표 두 개**로 보였다. 굵기를 500 → 700 으로 올려도
거의 달라지지 않았다. 반면 고딕 700 은 같은 글자를 굵은 막대 두 개로 그려 **한눈에 한자로 읽힌다.**

정리하면 — 명조는 **획순을 따라 쓰며 공부할 때** 유리하고, 고딕은 **글자를 알아볼 때** 유리하다.
이 게임은 후자다(학습·퀴즈·도감·대결이 전부 "알아보기"다).
나중에 획순 애니메이션을 넣는다면 그 화면에서만 명조를 쓰는 것을 검토한다.

덤으로 폰트 다운로드가 하나 줄어 초기 로드가 가벼워졌다.

### 크기 스케일 (fluid)

```
--text-hanja-hero: clamp(6rem, 22vw, 9rem)    한자 학습/퀴즈의 주인공 (모바일 하한을 올렸다)
--text-hanja-card: clamp(2rem, 7vw, 3rem)     도감 카드
--text-display-lg: clamp(1.75rem, 5vw, 2.5rem)
--text-display-md: clamp(1.375rem, 4vw, 1.75rem)
--text-body:       1rem  (모바일에서도 절대 14px 미만으로 내리지 않는다)
--text-small:      0.875rem
```

초등 저학년은 작은 글씨를 읽지 못한다. **본문 최소 16px**를 하한선으로 고정한다.

## 4. 형태 · 그림자 · 깊이

```
--radius-pill:   9999px
--radius-button: 1.125rem  (18px)
--radius-card:   1.5rem    (24px)
--radius-panel:  2rem      (32px)
```

모서리를 크게 둥글릴수록 "말랑한 장난감" 느낌이 난다. 각진 요소는 이 프로젝트에 없다.

```css
--shadow-soft: 0 2px 4px rgba(60, 40, 120, 0.06), 0 8px 20px rgba(60, 40, 120, 0.1);
--shadow-card: 0 4px 8px rgba(60, 40, 120, 0.08), 0 16px 32px rgba(60, 40, 120, 0.14);
--shadow-float: 0 8px 16px rgba(60, 40, 120, 0.1), 0 28px 56px rgba(60, 40, 120, 0.18);
--glow-magic: 0 0 0 4px rgba(124, 92, 255, 0.18), 0 8px 24px rgba(124, 92, 255, 0.36);
--glow-gold: 0 0 0 4px rgba(255, 201, 60, 0.22), 0 8px 28px rgba(255, 201, 60, 0.45);
```

그림자에 **회색이 아니라 보라(`60,40,120`)를 섞는다.** 회색 그림자는 화면을 탁하게 만든다.

### 버튼 입체감 (게임 UI의 핵심)

버튼 하단에 진한 색 테두리를 깔아 **물리적으로 눌리는 느낌**을 만든다.

```
기본:  translateY(0)   box-shadow: 0 6px 0 <color-700>
hover: translateY(-2px) box-shadow: 0 8px 0 <color-700>
press: translateY(4px)  box-shadow: 0 2px 0 <color-700>
```

이 한 가지 디테일이 "웹 버튼"과 "게임 버튼"을 가른다.

## 5. 모션

```
--dur-instant: 120ms   상태 토글
--dur-quick:   200ms   hover, press
--dur-normal:  320ms   카드 등장, 페이지 전환
--dur-slow:    560ms   보상 팝업
--dur-scene:   900ms   레벨업 시퀀스 1구간

--ease-pop:  cubic-bezier(.34, 1.56, .64, 1)   살짝 튀는 오버슈트 — 귀여움의 핵심
--ease-soft: cubic-bezier(.22, 1,    .36, 1)   부드러운 감속
--ease-in-out: cubic-bezier(.65, 0, .35, 1)
```

### 도구 분담

| 도구       | 담당                                                             |
| ---------- | ---------------------------------------------------------------- |
| **CSS**    | hover, press, focus, 단순 등장, idle float/blink (무한 루프)     |
| **GSAP**   | 다단계 타임라인 — 레벨업, 보상 카드 뒤집기, 도감 획득, 콤보 연출 |
| **PixiJS** | 대결 화면의 파티클·데미지 숫자·스프라이트 모션                   |

**규칙: 한 화면에서 동시에 주목을 요구하는 애니메이션은 1개.**
idle 모션(캐릭터 호흡, 구름 흐름)은 배경으로 취급하며 이 규칙에서 제외한다.

### `prefers-reduced-motion`

전역 CSS에서 무한 루프 애니메이션을 끄고, GSAP 타임라인은 `timeline.progress(1)`로
**즉시 최종 상태**로 보낸다. 연출을 건너뛰어도 게임 진행과 보상은 100% 동일해야 한다.

## 7. 캐릭터 아트 규칙 (인라인 SVG)

**공통 비례**: 머리 : 몸 = **1 : 1** (2등신). 아이가 "귀엽다"고 느끼는 비례다.

**눈**: 얼굴 폭의 22% 크기 원 + 흰 하이라이트 2개(큰 것 1, 작은 것 1).
하이라이트가 없으면 눈이 죽어 보인다. 이게 귀여움의 90%다.

**선**: 외곽선을 검정이 아니라 **자기 색의 어두운 톤**으로 그린다.

### 아군

| 캐릭터      | 특징                                                                  |
| ----------- | --------------------------------------------------------------------- |
| 한자 기사   | 둥근 투구, 커다란 방패(한자 문양), 짧고 뭉툭한 검, 밝은 웃음, 파랑+금 |
| 한자 마법사 | 몸통보다 큰 별 무늬 뾰족 모자, 짧은 망토, 구슬 달린 지팡이, 보라+민트 |

### 몬스터 (전부 "무섭지 않게")

| 지역 | 몬스터            | 모티프                              |
| ---- | ----------------- | ----------------------------------- |
| 1    | 꼬마 도토리 도적  | 도토리 몸 + 작은 복면, 삐뚠 이빨    |
| 2    | 물방울 장난꾸러기 | 물방울 + 찡긋 눈                    |
| 3    | 구름 뭉치         | 뭉게구름 + 볼터치                   |
| 4    | 무지개 여우       | 둥근 여우 + 무지개 꼬리             |
| 5    | 수정 아기 골렘    | 말랑한 보라 수정 덩어리             |
| 6    | 별똥별 요정       | 별 몸통 + 반짝이 꼬리               |
| 7    | 붓 마왕           | 커다란 붓을 든 작은 마왕, 귀여운 뿔 |

**몬스터 디자인 체크**: 이빨은 뾰족해도 2개 이하, 눈은 반드시 크고 둥글게,
피격 시 "화남"이 아니라 **"당황"** 표정으로 바뀐다.

## 9. 화면별 디자인 의도

| 화면            | 한 줄 의도                                                        |
| --------------- | ----------------------------------------------------------------- |
| 메인            | 대시보드가 아니라 **모험 지도**. 캐릭터가 서 있고 지역이 이어진다 |
| 회원가입/로그인 | 폼이 아니라 **"탐험대 입단"**. 캐릭터가 말풍선으로 말을 건다      |
| 캐릭터 선택     | 두 캐릭터가 나란히 서서 손을 흔든다. 선택 시 앞으로 한 걸음       |
| 한자 학습       | **아이템 획득 연출**. 한자가 빛과 함께 등장한다                   |
| 퀴즈            | 시험지가 아니라 **대결 장면**. 정답 = 마법 발사                   |
| 도감            | 못 배운 한자는 실루엣. 채워질수록 마법서가 빛난다                 |
| 레벨업          | 암전 → 빛기둥 → 캐릭터 → 별 파티클 → LEVEL UP → 보상              |
| 대결            | PixiJS 무대. HP 바, 데미지 숫자, 승리 시 폭죽                     |

## 10. 디자인 완료 판정 체크리스트

PHASE 18 및 각 화면 완료 시 이 목록으로 검수한다.

- [ ] 화면에 "주인공"이 명확히 하나 있는가
- [ ] 아이가 다음에 뭘 눌러야 할지 1초 안에 아는가
- [ ] 보상이 즉시·시각적으로 보이는가 (숫자만 바뀌지 않는가)
- [ ] 캐릭터/몬스터가 귀여운가 (무섭지 않은가)
- [ ] 버튼이 "누르고 싶게" 생겼는가
- [ ] 모바일 390px에서 가로 스크롤이 없는가
- [ ] 텍스트가 잘리거나 겹치지 않는가
- [ ] 터치 타깃이 48px 이상인가
- [ ] 색만으로 정보를 전달하는 곳이 없는가
- [ ] 애니메이션을 껐을 때도 모든 기능이 동작하는가
